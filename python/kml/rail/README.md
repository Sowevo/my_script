# 铁路/地铁/轻轨/单轨 OSM 轨道递归提取与可视化系统

## 功能简介
- 基于 OSM PBF 文件，递归提取铁路/地铁/轻轨/单轨轨道的 way 列表，支持 `rail`、`subway`、`light_rail`、`monorail`。旧索引需重新生成后才能搜索新增类型。
- 支持自动/手动推进轨道链路，智能推荐分支。
- 可视化轨道链路、分支、全局累计链路，支持地图交互。
- 支持一键复制全局累计链路为 Overpass Turbo 查询格式。
- 前端采用 Leaflet+Bootstrap5，交互美观流畅。

## 依赖环境
- Python 3.9+
- Python 依赖统一在 `requirements.txt` 中管理，固定为已验证的直接依赖版本。
- Bootstrap 5 (前端CDN)
- Leaflet.js (前端CDN)

## 1. 获取 PBF 下载地址

支持 Geofabrik 提供的各个区域，不限于特定国家。获取所需区域的链接：

1. 打开 [Geofabrik 下载站](https://download.geofabrik.de/)。
2. 选择洲，再选择国家或地区；部分国家还提供省、州等更小区域。
3. 在目标区域页面找到 `.osm.pbf` 下载项，右键复制链接地址。

请复制文件的下载链接，而不是 `.html` 详情页地址。不同地区的 URL 层级可能不同，直接从页面复制，不要只替换国家名称来拼接 URL。日本的 `https://download.geofabrik.de/asia/japan-latest.osm.pbf` 仅是链接格式示例。

## 2. 生成索引

**2.1 和 2.2 任选其一即可，无需都执行。** 必须传入下载链接或本地 PBF 路径；未传参数时会提示用法并退出。已有完整索引且不需要更新地图数据时，可直接进入第 3 节启动服务。

每次解析只处理一个 PBF，并覆盖现有六份索引，不会合并多个文件。更新索引前先停止网页服务，生成完成后再启动。

### 2.1 自动下载并生成索引

安装好 Python 依赖后，在 `rail/` 下执行，将示例 URL 替换成你复制的下载链接：

```bash
cd "/Users/sowevo/git/self/my_script/python/kml/rail"
source ".venv/bin/activate"
python "app/parse_osm.py" "https://download.geofabrik.de/asia/japan-latest.osm.pbf"
```

下载由 Python 标准库实现，无需安装 aria2 或其他下载工具。支持最多 16 个连接并行分段下载、断点续传和 HTTP/HTTPS 重定向，最小分段大小为 1 MiB；实际连接数取决于文件大小。下载成功后自动提取轨道并保存索引，无需手动选择下载目录。

同一链接使用固定目录；下载中断时保留 `.partial` 分段和 `download.json` 进度记录，重新执行同一命令即可续传。脚本先核对远端文件大小及 ETag/Last-Modified；版本未变则续传或复用完整文件，版本变化则重新下载。下载失败不会开始解析。

服务器不支持 Range 时自动使用单连接完整下载；未提供可靠版本标识时，跨次运行会重新下载，避免拼接新旧数据。分段下载完成后合并为 `source.osm.pbf`，自动清理分段文件；合并期间需额外容纳一份 PBF 的磁盘空间。

### 2.2 手动下载后传入路径生成索引

使用上面获取的链接，通过浏览器或下载工具将 PBF 下载到本地（已有文件可直接使用），然后在 `rail/` 下传入实际文件路径：

```bash
cd "/Users/sowevo/git/self/my_script/python/kml/rail"
source ".venv/bin/activate"
python "app/parse_osm.py" "/实际路径/地图.osm.pbf"
```

本地文件直接读取，不复制或删除原文件。

### 2.3 保存位置介绍

#### 下载文件

自动下载时，脚本查询系统 Downloads 目录（macOS 使用系统目录查询，Linux 使用 `xdg-user-dir DOWNLOAD`；查询不可用时回退到当前用户主目录下的 `Downloads`），文件保存在其中的 `rail/<链接哈希>/source.osm.pbf`。例如本机为 `/Users/sowevo/Downloads/rail/<链接哈希>/source.osm.pbf`；续传分段和进度记录也保存在同一目录。

手动下载的 PBF 保留在你选择的位置，脚本只读取传入的文件。

#### 索引文件（两种方式通用）

看到“索引已保存”后，脚本所在目录的 `data/`（即 `rail/app/data/`）下会生成五份缓存，不受终端当前目录影响。整个 `app/data/` 已由仓库根目录的 `.gitignore` 忽略：

- `node_to_ways.pkl`：节点与轨道的连接关系。
- `way_to_nodes.pkl`：每段轨道包含的节点。
- `node_coords.pkl`：相关节点的经纬度。
- `way_to_meta.pkl`：轨道名称、类型等属性。
- `relations.pkl`：轨道所属的 OSM 关系及父关系，保存标签、成员顺序和角色。

索引生成后可以删除原始 PBF，只需保留这六份索引；不影响网页运行或重启。

已有轨道索引时，可仅补建本地站点索引（使用与轨道索引相同的 PBF）：

```bash
python "app/parse_osm.py" --stations-only "/你的路径/区域.osm.pbf"
```

生成 `app/data/stations.pkl` 后重启服务即可。正常生成索引时会同时生成站点索引。站名查询不联网，也不会重新按线路关系推进轨迹。

## 主要用法
- 地图右上角可在线搜索城市、车站、机场或地址，点击结果定位。使用 OSM Nominatim 地名服务，需要联网，无需重建 PBF 索引；可搜索全球地点，但轨道和关系仍仅查询本地已导入区域。
- 地点搜索在当前浏览器保存最近10条有结果的搜索词，重复搜索移到最前。点击输入框可查看历史，输入文字可筛选，点击历史重新搜索；支持清空，刷新后保留。浏览器禁止本地存储时仅在当前页面暂存。
- 地名搜索仅在提交时请求，不做逐字补全；服务端缓存结果24小时（最多256条），单个服务进程请求间隔至少1秒。可通过 `RAIL_GEOCODER_URL` 配置兼容 Nominatim 的搜索服务地址。
- 在地图上靠近轨道的位置右键，在菜单中选择100/250/500米，查询附近轨道与其所属的 OSM 关系；轨道按距离排序。
- 点击轨道或关系查看标签并高亮；“缩放到此要素”显示完整的本地几何。轨道可点击“从此轨道开始探索”。
- 关系成员按 OSM 原始顺序列出，并展示角色；可点击已收录的轨道或子关系继续查看。关系高亮只包含本地索引中的轨道，未收录的车站、站台等成员仅显示信息。
- 右键菜单提供100/250/500米三个同等选项；选中后查询右键位置，半径不随地图缩放变化。点击菜单外或按 Escape 关闭菜单。最多显示最近50段轨道，结果太多时减小半径或调整查询位置。所属关系包含父关系，可能延伸到查询范围以外。
- 所有查询使用当前 PBF 的本地索引，不在线查询 OSM；旧索引需要重新生成才能查看关系。
- 也可以直接输入数字 way_id，点击“开始探索”。
- 地图初始视野按当前索引中的轨道坐标范围自动定位，选择起点后缩放到已选轨道。
- 地图放大到 16 级后用紫色火车图标高亮车站，默认不叠加文字；悬浮显示完整站名及线路，不做文字避让或距离聚合；按视野加载，每次最多 500 站。
- 仅显示明确标记的铁路车站。同一 `stop_area` 显示一个点，无关系的车站独立显示，不按同名合并。站台、停车点、出入口和站房不单独显示，不再解析或绘制轮廓。
- 线路取自真实运行关系，优先采用 `route_master` 并合并同一线路的上下行。站台与停车点关联仍用于 KML 端点命名。

- 旧站点索引建议运行 `--stations-only` 补建后重启，以保存车站节点类型并得到更准确的标记位置。
- 点击候选行右侧的双右箭头，每次仅前进该条轨道，不连续自动推进；双右箭头和定位按钮整体右对齐。单步前进和退回均保持地图视口不变。
- 点击“退回一步”通常移除当前段末尾的一条 way；刚截断时则恢复截断前的完整本段。如果截断后又添加轨道或换乘，先逐条退掉新轨道，再恢复截断。连续截断也按逆序恢复。悬浮按钮时，红色预览要移除的部分，绿色预览要恢复的部分；整个操作不移动地图。该段退空后回到上一段，全部退空则回到未选择状态。
- 点击右键菜单“在此结束本段”后直接截断，不弹确认框。只在本段最后一条 way 已保留的区间内找最近投影点，不参与选择其他轨道；投影附近 25 米内有该 way 的本地停车点时优先吸附。点击距离超过 150 米则提示重新选择；目标在更早的 way 上时先退回。方向未确定时提示先用“从此开始本段”选择起点和方向，不再弹候选框。误操作用“退回一步”恢复，地图视口不动。
- 前进端接回本段已走过的轨迹时，停止本段自动推进，即使连接处还有其他出口也不再继续；普通的前后轨道连接不算闭合，起始 way 被排除在行程外的部分也不算已走过。可退回一条轨道重新选择。
- 截断保留实际坐标区间，地图、距离、导出端点和 KML 同步更新。Overpass 只能查询完整 way，不能表达部分轨道；需要准确截断位置时直接下载 KML。
- 不指定起点时保持原流程：输入轨道 ID 或点击“从此轨道开始探索”，按整条 way 开始探索，不展示 A/B。中途上车时先在附近列表选中 way，确认所属关系后，在地图上右键“从此开始本段”；此时原轨道列表才显示 `111-A（西武新宿線）` / `111-B（西武新宿線）` 两侧候选。继续查看所属关系不会丢失选中的 way。候选沿用悬浮高亮、双右箭头和定位按钮，没有额外的选点操作框；只有选定 A/B 才加入从该点出发的轨迹。
- 已有行程时输入新轨道 ID 或点击“作为下一段继续”，按原流程追加整条轨道的新段；在所选 way 上右键“从此开始本段”则可从中途起步，选择 A/B 后再追加新段。
- 每段行程独立记录轨道，地图使用该段起始轨道的 `colour`，无有效标注时按行程段轮换蓝、紫、青绿、橙、红色；KML 使用相同颜色，不绘制跨线连接。刷新页面回到未选择状态，不再自动恢复行程。地点搜索历史不受影响。
- 点击“下载 KML”直接使用本地索引导出一个文件，每段行程为独立的 Placemark，换乘处不连线。同段轨道仅在端点重合时拼接，存在缺口或分叉时在 MultiGeometry 中保留独立线段。世界迷雾对该结构的实际导入效果需在应用中验证。
- 导出范围可选择全部行程或单段，生成Overpass查询时对轨道ID去重。“从此轨道开始探索”仅在没有行程时显示；重新开始请刷新页面，保留已有行程可直接输入新轨道 ID 或点击“作为下一段继续”。下载前从 PBF 站点索引查询每段轨迹两端：优先在端点轨道的停车点及所属线路的停靠站中选择离端点最近的一站，再使用 1.5 公里内的本地附近车站作为建议；无关联数据时标明“附近车站”。可选择候选站、手动修改、删除重复换乘站或反转站名顺序；文件名为“起点站 → 换乘站 → 终点站.kml”。起点、终点、换乘及候选站名统一优先使用 PBF 原始 `name`，缺失时依次使用 `name:zh`、`name:ja`、`name:en`。站名优先取成员所属的 `stop_area`，其次使用要素自身名称，不使用 `stop_area_group` 命名或合并。同一 `stop_area` 的同名换乘站自动合并，不同站点保留两项供修改，导出时显示为“到达站（出发站）”，例如“A → B1（B2） → C.kml”，KML 文档名称同步更新。查询失败或没有附近车站时可手动填写，轨道几何仍使用本地索引；切换导出范围不改变全部行程的统计。
- 可选相连轨道用 ⭐ 标记推荐项：根据共享节点确定进入方向，优先前方端点接续，再比较站场属性、名称和连接处转角。方向不明确时不标星，所有候选仍可手动选择。
- 默认完整展示当前轨道，候选从连接处延伸500至2000米参与缩放；悬停或键盘聚焦只高亮，不移动地图。轨道旁准星可查看完整几何，当前轨道旁准星恢复默认视野；地图加减按钮下的全览图标仅在有行程时显示。候选支持回车选择。
- 地图支持轨道高亮、自动缩放、全局累计链路可视化。
- 探索结果显示已选轨道数量及手动/自动推进数量；点击“复制 Overpass 查询”后，可自行粘贴到 Overpass Turbo 运行，再通过其导出菜单获取 GeoJSON / KML。“查看查询内容”可展开检查完整查询。

## 常见问题
- **生成索引后能删除 `.osm.pbf` 吗？** 可以。PBF 仅用于生成索引，网页版启动和运行都不再读取它；删除后不影响当前服务，以后也能正常重启。请保留 `app/data/` 中的六份索引：`node_to_ways.pkl`、`way_to_nodes.pkl`、`node_coords.pkl`、`way_to_meta.pkl`、`relations.pkl`、`stations.pkl`。只有更新地图数据或重新生成索引时，才需要再次提供 PBF 文件。
- **PBF 解析慢/内存高**：建议裁剪区域或用更大内存机器。
- **轨道不显示**：请确保 `node_coords.pkl` 文件不为空，且已重新生成索引。
- **复制/粘贴问题**：如浏览器限制剪贴板访问，请手动复制。
